Ты — `reverse-engineer` agent. Активируй ADR-0006 (mirror app behavior).

**Last reviewed:** 2026-10-05 (разбор «Мой Дом» 9.10.0 → 9.11.0)

## Параметр

`$ARGUMENTS` — целевая версия, например `9.10.0`. Если пустое — выяснить последнюю по шагу 1 и спросить подтверждение.

## Что этой процедурой закрывается

Два разных вопроса, и не путать их: **«какой `versionCode` писать в `const.py`»** и **«что изменилось в API»**. Первый решается за минуту, второй требует бинарника. Если нужен только первый — шаг 1 может хватить, но см. ловушку в шаге 5.

## 1. Узнать версию и `versionCode` без скачивания

Карточка приложения в [RuStore](https://www.rustore.ru/catalog/app/ru.inetra.intercom) отдаёт JSON прямо в HTML. В одном объекте лежат `packageName`, `versionName`, `verCode` и издатель — это запись самого приложения, а не догадка по названию:

```bash
curl -sS -A 'Mozilla/5.0' -L https://www.rustore.ru/catalog/app/ru.inetra.intercom -o /tmp/rustore.html
python3 - <<'PY'
import re, pathlib
s = pathlib.Path("/tmp/rustore.html").read_text(errors="replace")
i = s.find('\\"verCode\\"')
print(re.findall(r'\\?"(?:packageName|versionName|verCode)\\?"\s*:\s*\\?"?([^",}\\]+)', s[i-3000:i+3000]))
PY
```

Схема `versionCode` в этом приложении: `major·10⁷ + minor·10⁵ + patch·10³ + build`. Для 9.9.0 это `9·10⁷ + 9·10⁵ + 20 = 90900020`, для 9.10.0 — `91000020`. Схема годится **для проверки** полученного числа, но не для его вывода: `build` из версии не следует.

🔴 Дата публикации в RuStore — это дата публикации **в RuStore**, а не дата релиза. Расхождение на неделю нормально и само по себе не значит, что сборка другая.

## 2. Найти файл

`curl` к зеркалам упирается в Cloudflare (`403`, тело — «Just a moment...»). Нужен настоящий браузер:

1. Открыть страницу загрузки на [apkcombo](https://apkcombo.com/-/ru.inetra.intercom/download/apk) браузерным инструментом (Playwright MCP).
2. Собрать варианты со страницы — у каждого в подписи стоит `versionName (versionCode)`:
   ```js
   [...document.querySelectorAll('a.variant')].map(a => ({href: a.href, text: a.innerText}))
   ```
3. Перейти браузером **прямо на файловый URL** (он лежит в base64 внутри параметра `u=` ссылки `apkcombo.com/d?u=...`). Загрузка стартует в браузере, Cloudflare пропускает.

Файл падает в `.playwright-mcp/` рабочей директории **с искалеченным именем** (percent-encoding кириллицы превращается в `-D0-9C-...`) — искать по размеру, а не по имени:

```bash
ls -l .playwright-mcp | awk '$5 > 5000000'
```

`find … -newermt '-30 minutes'` здесь не годится: `find` в окружении может оказаться `bfs`, а он относительное время не принимает и падает на каждом вызове. `ls -l` одинаково работает в BSD и GNU; свежий файл — тот, чей размер совпал с заявленным.

Размер должен совпасть с параметром `s=` из метаданных ссылки. Перенести файл из `.playwright-mcp/` (эта папка внутри репозитория) в `research/apk/` под именем `myhome-<версия>-original.<ext>`.

## 3. Проверить подпись — это то, что делает зеркало приемлемым

Зеркало не источник истины, а транспорт. Доверять скачанному можно, если пакет проходит проверку подписи **и** его подписант совпадает с известным хорошим пакетом.

Одного отпечатка мало, и это не теория: если у подлинного APK перевернуть байт в середине, не тронув блок подписи, отпечаток останется прежним. Поэтому `apk-cert.py` проверяет схему v2 целиком — подпись над `signed data` открытым ключом, соответствие сертификата этому ключу и пересчитанный дайджест всего содержимого. Совпадение отпечатка ловит пересборку чужим ключом; дайджест ловит подмену содержимого.

Проверяется сам `.apk`, а не контейнер: XAPK и APKS — zip-архивы зеркала без своей подписи, их сначала распаковать (шаг 4) и проверять base-APK и сплиты. Контейнер целиком скрипт отклонит. Нужен пакет `cryptography` (есть в `.venv`).

```bash
python3 research/scripts/apk/apk-cert.py \
    research/apk/myhome-<известная>-original.apk \
    x/ru.inetra.intercom.apk
```

Скрипт печатает по файлу `✅ подпись v2 сходится, дайджест содержимого сходится` и отпечаток, а на два файла — ещё и вердикт о подписанте. Любой `🔴` — стоп, файл не использовать. Эталон для «Мой Дом» зафиксирован в `research/apk/9.9.0-analysis.md`.

`keytool -printcert -jarfile` здесь бесполезен: он читает только v1-подпись (META-INF), а эти пакеты подписаны схемами v2/v3 и он отвечает «Not a signed jar file». `apksigner` сделал бы то же самое, но тянет весь Android SDK.

## 4. Достать манифест

XAPK — это zip с `base.apk` и сплитами; распаковать и работать с базовым:

```bash
unzip -q myhome-<версия>-original.xapk -d x/
apktool d -f -s -o dec x/ru.inetra.intercom.apk
grep -A3 'versionInfo\|sdkInfo' dec/apktool.yml
```

🔴 `jadx --no-src` манифест **не отдаёт** — не тратить на это круг. `apktool d -s` (без дизассемблирования smali) быстрый, и `versionCode`/`versionName`/`minSdkVersion` лежат прямо в `apktool.yml`.

🔴 `manifest.json` внутри XAPK написан зеркалом, а не издателем. Это метаданные посредника: сверять по нему можно, доказывать — нет.

## 5. Ловушка вариантов: `minSdkVersion` из скачанного файла не равен объявленному

Play собирает из одного bundle несколько наборов APK под разные диапазоны устройств, и зеркала раздают их все под одним `versionCode`. У варианта, помеченного «Android 6.0+», в манифесте `minSdkVersion: 23` — это таргетинг **этого набора**, а не минимум приложения. На разборе 9.10.0 отсюда родился ложный вывод «minSdk понизили с 32 до 23»; установленное на телефоне приложение показывало 32.

Правило: `versionCode`, пути эндпоинтов и DTO достоверны для **этого файла** (проверка подписи это гарантирует), но `minSdkVersion` описывает вариант, а не приложение. Если он нужен — брать с устройства:

```bash
adb shell dumpsys package ru.inetra.intercom | grep -E 'versionCode|minSdk|targetSdk'
```

## 6. Диф эндпоинтов — до декомпиляции, а не после

`jadx` на этих пакетах идёт минуты и даёт ~19 тысяч файлов. Чтобы узнать «что нового», он не нужен: пути лежат в таблице строк dex.

```bash
python3 research/scripts/apk/apk-endpoints.py \
    research/apk/myhome-<старая>-original.apk \
    x/ru.inetra.intercom.apk
```

Декомпилировать дальше — только то, что показал диф.

Почему нельзя просто грепать строки глазами: в dex длина строки идёт ULEB-префиксом, и его байт часто попадает в печатный диапазон, поэтому в сыром выводе путь выглядит как `.api/...` или `;api/...`. И второе — JVM-дескрипторы (`Lcom/ertelecom/...;`) тоже полны слэшей, а между релизами у них меняется обфусцированное имя `Continuation` (`Lkm0/d;` → `Lcn0/e;`), из-за чего каждый метод читается как «удалён и добавлен». Скрипт отсекает и то, и другое.

## 6a. Найти фичу в интерфейсе — по ресурсам, а не по коду

`apktool d -s` декодирует **ресурсы** (пропускает только smali), поэтому `dec/res/values/strings.xml` — самый быстрый способ понять, как функция называется в приложении и где живёт. Префикс имени строки выдаёт feature-модуль: `access_keys_temp_pass_*` означает раздел ключей, а не «Люди».

Это же отвечает на вопрос «почему пользователь фичу не видит»:

- строки нет вовсе → функции в этом приложении нет, и скриншот, скорее всего, из другого приложения оператора (у них разные бэкенды — см. `research/apk/README.md`);
- есть пара состояний `*_not_active_*` с кнопкой «Подключить» → вход в функцию оформлен как **подключение managed-услуги**, а включена ли она на адресе, решает сервер. Отличить неподключённую услугу от ещё не раскатанной функции этот признак не позволяет, и о платности он ничего не говорит. Признак в коде: строковый идентификатор уходит как `managed_service` в `ManagedServiceConnectActivity` / `ManagedServiceActiveActivity`;
- у промо-баннера есть DTO со флагом вида `isBannerClosed` → баннер закрывается навсегда и по каждому адресу отдельно, так что «баннер пропал» не значит «функции нет».

Для интеграции вывод из такого разбора важнее самих путей: если вход в функцию оформлен как подключение, её доступность определяется не версией приложения, а состоянием услуги на конкретном адресе, и действие обязано это учитывать.

Проследить навигацию до экрана по id ресурса обычно **не** выходит: числовые id в base-dex не встречаются. Ограничивайся именами строк и классов Activity.

## 7. Восстановить контракт нового сервиса

```bash
jadx -j 4 --no-res -d src <base>.apk
python3 research/scripts/apk/apk-contract.py src/sources <подстрока-сервиса>
```

Печатает Retrofit-интерфейсы (метод + путь) и для каждого DTO — имена полей **на проводе**.

Имена аннотаций Retrofit R8 переименовывает в каждой сборке по-своему (`@POST` был `pt0.o` в 9.10.0 и стал `vg8` в 9.11.0), поэтому скрипт не держит их таблицу, а читает соответствие из `RequestFactory` самого Retrofit. Короткое написание аннотации засчитывается, только если файл её импортирует или лежит в её пакете: в 9.10.0 `@o` — это и Retrofit `@POST`, и Moshi `@Json`. Если подстрока в коде есть, а вызов с ней не распознан, скрипт завершается ошибкой: пустой вывод выглядел бы как «эндпоинтов нет».

Откуда берутся имена, если R8 переименовал поля в `f6779a`, а `@Metadata.d2` у релизной сборки вычищен:

- `toString()` data-класса Kotlin — компилятор зашивает имена свойств литералами;
- `JsonReader.Options` в сгенерированном `<Class>JsonAdapter` — там имена **на проводе**.

Второе авторитетнее: расхождение означает `@Json(name = ...)`, и брать надо провод. Не брать все строковые литералы адаптера подряд — там же лежит имя Kotlin-модуля из `@Metadata` (`accesskeys_ntkRelease`), и оно уедет в вывод как поле DTO.

## 8. Записать результат

- Разбор — в `research/apk/<версия>-analysis.md` по образцу `research/apk/9.9.0-analysis.md`: версия, `versionCode`, отпечаток подписанта, что добавилось, что удалилось.
- Новые эндпоинты, которых у нас нет, — finding в `docs/audit/project-audit.md` и задача в tasklist соответствующей фичи.
- Если менялся `versionCode` — `APP_VERSION` в `const.py`. Это `custom_components/**`, то есть **требует подтверждения пользователя**.

🔴 **ADR-0006.** Всё, что добыто из бинарника, — статическое доказательство. Оно говорит, что клиент **умеет** так позвать; оно не говорит, что сервер так отвечает, какие значения допустимы и какие поля обязательны. В `docs/architecture/api-reference.md` такой эндпоинт идёт с пометкой «static-only» и ссылкой на разбор; реализовать его можно, если приложение этой версии его вызывает, а приёмка — по первому живому подтверждению: HAR (`.agents/commands/capture-har.md`), живая проба исследовательским аккаунтом или отчёт пользователя.

🔴 **Приватность.** Скриншоты и снимки экранов приложения содержат реальный адрес, названия объектов и кадры с камер. В коммитируемые артефакты идёт только состав экрана и имена полей — никаких значений (правило S-25 в `docs/audit/security.md`).
