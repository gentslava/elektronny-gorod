# Markdown: не переносить строки вручную

Абзац, пункт списка и ячейка пишутся **одной строкой любой длины**. Перенос делает редактор, а не автор.

## Почему

Ручной перенос посреди фразы ломает чтение в редакторе с мягким переносом и делает diff шумным: правка одного слова перекладывает весь абзац, и в ревью не видно, что изменилось по существу.

Накапливается это незаметно. Генератор текста переносит по привычной ширине, замечания в ревью на такое не тратят, и за несколько сессий файл оказывается размечен вручную целиком. Владелец репозитория правил это повторно, прежде чем правило было записано.

## Что считается нарушением

Перенос **посреди предложения**: предыдущая строка длинная и не оканчивается знаком конца фразы, а следующая продолжает ту же мысль.

Внутри пункта списка нарушением считается любое продолжение с отступом: строка с отступом там всегда продолжает тот же пункт, намеренным разрывом быть не может. Для структуры внутри пункта используют вложенный список или пустую строку.

## Что переносом не считается

Перенос значим и его не трогают:

- YAML-фронтматтер — там значим каждый перевод строки;
- HTML-разметка — блоки `<p>`, `<table>`, `<tr>` читаются построчно;
- таблицы, блоки кода, заголовки, цитаты;
- явный перенос markdown из двух пробелов в конце строки;
- строка, оканчивающаяся точкой, двоеточием, точкой с запятой или скобкой — после двоеточия обычно идёт список, а после точки разрыв мог быть поставлен нарочно;
- короткая строка (меньше 60 символов) — по ширине её никто не переносил, значит разрыв намеренный. Так пишут поля вида `**Статус:** согласовано`, идущие подряд.

## Как проверить и исправить

```bash
bash .agents/hooks/check-markdown-wrap.sh          # проверка, exit 1 при нарушениях
bash .agents/hooks/check-markdown-wrap.sh --fix    # исправить
bash .agents/hooks/check-markdown-wrap.sh FILE.md  # только один файл
```

Проверка и исправление — один и тот же код, поэтому разойтись они не могут. Правка гарантированно меняет только пробелы: если нормализация задела бы текст, файл пропускается с предупреждением.

Для Claude хук подключён на `PostToolUse` для `Edit` / `Write` через `.claude/settings.json`.

## Границы

Правило про **мои** правки. Чужие абзацы, размеченные вручную, переформатировать заодно не нужно: это распухший diff вместо содержательного. Исключение — отдельная задача на приведение файла в порядок, как это было сделано один раз для всего репозитория.
