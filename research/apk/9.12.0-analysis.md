Это включает auth, places, cameras, accesscontrols, events, STOMP feature probe, push-регистрацию, `sipdevices`, guests, temporary access и finance. Обёртка STOMP `SocketPayloadAdapter` по-прежнему читает `type` / `payload`. Частота запросов, runtime FCM/SIP и ответы сервера 9.12.0 этим сравнением не подтверждены.

`jadx` завершился с частичными ошибками декомпиляции (265 в 9.11.0, 261 в 9.12.0; exit 3). Перечисленные декларации и описанные ниже DTO/адаптеры доступны в декомпиляте; выводы не основаны на телах методов, которые JADX не восстановил.

## Изменение DTO: временный доступ `openCount`

Сравнение таблиц имён полей Moshi (`JsonReader.Options`) нашло 301 таблицу в 9.11.0 и 300 в 9.12.0. Изменения ограничены семейством temporary access:

- Удалены дублирующие `feature/accesskeys/data/api/TempPassRaw` и `TempPassAccessControlRaw`; POST теперь использует DTO из `shared/sync/data/api/temppass`, как GET списка.
- В `shared/sync/data/api/temppass/TempPassRawJsonAdapter.java` добавлено поле `openCount`.
- Новый `OpenCountRawJsonAdapter.java` читает `left` / `max` как `int`; внутри объекта оба поля обязательны и не допускают `null` в клиентском парсере. Сам `openCount` необязателен: пропущенное поле и JSON `null` дают `null` в `TempPassRaw`.

Статическая форма ответа GET списка и POST создания:

```text
TempPassRaw {
  id, sharedLinkMessage, status, expiredAt,
  availableAccessControl: [{id, name, roleName}],
  openCount: null | {left: int, max: int}
}
```

Это ограничение клиентского парсера, а не доказательство обязательности полей на сервере. В ресурсах 9.12.0 есть `access_keys_temp_pass_limit_title` («Осталось открытий») и `access_keys_temp_pass_limit_value` (`%1$d из %2$d`). DTO-маппер `y5e.Z` переносит `openCount` в локальную модель. Реальные значения, диапазоны, обновление счётчика и доступность по адресу требуют HAR/живой проверки.

`apk-contract.py <sources-9.12.0> mh-temp-pass` подтвердил прежние пять вызовов (`syb.java`, `tyb.java`), включая DELETE с телом:

```text
GET    .../temp-passes?placeId=                 → [TempPassRaw]
GET    .../temp-passes/access-controls?placeId= → [{id, name}]
GET    .../temp-passes/time-to-life?placeId=     → [long]
POST   .../temp-passes                         {placeId, ttl, accessControlIds} → TempPassRaw
DELETE .../temp-passes/{id}                    {placeId}
```

Нового параметра лимита в `CreateTempPassRequestRaw` нет. Остальные таблицы имён полей Moshi совпали; само совпадение имён не доказывает неизменность всей бизнес-логики.
