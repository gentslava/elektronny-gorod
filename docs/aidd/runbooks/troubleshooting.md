# Runbook: Troubleshooting

Когда пользователь приходит с проблемой — что спрашивать, что подсказать.

## Шаг 0: Запросить базовую информацию

В issue или discord:

1. Версия HA Core: Settings → About.
2. Версия интеграции: из HACS / `manifest.json`.
3. Что пытались сделать.
4. Что произошло.
5. Diagnostics для проблемной config entry из Home Assistant.
6. Если diagnostics недостаточно — короткий релевантный фрагмент лога с debug только для нужного модуля (см. [`debugging.md`](debugging.md)).

Интеграция редактирует известные секреты и персональные поля в diagnostics, но перед публикацией файл всё равно нужно просмотреть. Полный `home-assistant.log` не нужен: сторонние зависимости могут записать токены, заголовки авторизации или персональные данные в собственных сообщениях.

## Частые проблемы

### «Интеграция не появляется в списке после установки»

- HACS не подхватил релиз → restart HA после установки через HACS.
- Файлы попали не в тот `custom_components/`.

### «Config flow зависает / ошибка `unknown_status`»

- API оператора недоступен временно.
- Сменился ToS / API — нужен update.
- Проверить логи: какой endpoint возвращает 500/502.

### «`invalid_phone` несмотря на корректный номер»

- Номер передаётся оператору в том виде, как введён. Использовать тот же формат, который принимает официальное приложение, без пробелов и разделителей.
- Если формат тот же, ошибка означает отказ API оператора; приложить diagnostics и время попытки без публикации самого номера.

### «`limit_exceeded` при запросе SMS»

- Оператор лимитирует SMS. Подождать 5-15 минут.
- Использовать **password** или **access_token** ветку config_flow вместо SMS.

### «Камера показывает `unavailable` всегда»

- Проверить в diagnostics, загрузились ли камеры и успешно ли обновился coordinator.
- Проверить доступность API оператора и короткий фрагмент лога вокруг `UpdateFailed`.
- Если проблема только с видео — отдельно проверить доступность go2rtc и источник потока.

### «Снимок камеры не обновляется»

- `async_camera_image` не запрашивает снимок для скрытой или недоступной камеры; при успешном запросе последний снимок сохраняется в cache.
- Возможные причины: временная ошибка API оператора, истёкшая авторизация или недоступная камера. Проверить diagnostics и релевантный фрагмент лога.

### «Открытие замка отрабатывает, но lock остаётся `locked`»

- Это ожидаемая модель домофона: после успешной команды entity кратко показывает `unlocked`, затем возвращается в `locked`, потому что API не сообщает физическое состояние двери.
- Если состояние вообще не меняется, проверить доступность entity и ошибку запроса открытия в логе.

### «Низкий баланс не вызывает автоматизацию»

- Данные обновляет coordinator с интервалом интеграции, поэтому автоматизация срабатывает только после получения нового значения, а не сразу после оплаты или списания у оператора.
- Проверить время последнего успешного обновления и условие/trigger автоматизации; для немедленной проверки можно выполнить Reload интеграции.

### «go2rtc валидация падает с `go2rtc_unreachable`»

- Проверить URL: должен быть `http://HOST:PORT` без trailing slash.
- Проверить network: HA должен иметь доступ к go2rtc.
- Если go2rtc требует Basic Auth — указать username/password в настройках интеграции.
- Логи go2rtc на той стороне.

### «После рестарта HA — entity disappeared»

- Проверить, загрузилась ли config entry и есть ли устройства/сущности в diagnostics; старт может не завершиться при ошибке первого обновления.
- Возможные причины: истёкшая авторизация, временная ошибка API оператора или изменившийся список доступных объектов аккаунта.
- Сначала выполнить Reload; если авторизация больше не принимается — повторно подключить аккаунт через UI с теми же данными.

## Когда эскалировать

- Если симптом не покрыт выше — issue в [GitHub](https://github.com/gentslava/HA-ElektronnyGorod/issues).
- Перед открытием issue — поискать существующие открытые.

## Что не помогает пользователю

- ❌ «Переустановите HACS» (редко помогает, маскирует проблему).
- ❌ «Удалите и пересоздайте entry» (теряется история).
- ❌ «Обновите HA до самой свежей» (часто не относится).

## Что обычно помогает

- ✅ Перезапустить именно интеграцию (Reload через UI).
- ✅ Проверить лог конкретно за `custom_components.elektronny_gorod`.
- ✅ Reauth через config_flow с тем же номером.
- ✅ Скачать pre-release из PR с фиксом (через HACS Custom repository), если фикс готов. Для PR из форка сборка появляется после того, как мейнтейнер одобрит прогон во вкладке Actions.
