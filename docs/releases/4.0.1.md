# v4.0.1 — Звонки снова доходят, FCM не зацикливается

**Это обязательное исправление для пользователей 4.0.0.** Оператор изменил формат служебных заголовков push-сообщений, и библиотека FCM перестала разбирать звонки. Один такой push мог не только потерять событие вызова, но и запустить повторную доставку с постоянно растущим журналом; в одном из сценариев Home
Assistant переставал отвечать.

| | Главное |
|---|---|
| 📞 **Звонки снова в Home Assistant** | Входящий FCM-push снова доходит до event entity, экрана вызова и автоматизаций |
| 🧯 **Без зависания и гигабайтных логов** | Ошибочное соединение закрывается конечным предохранителем вместо горячего цикла в event loop |
| 🩺 **Управляемое восстановление** | Повторные сбои ограничены одним аккаунтом, показаны в Repairs и проверяются с безопасным backoff |

> ✅ **Без breaking changes.** Повторно добавлять интеграцию, проходить
> авторизацию или перенастраивать сущности не нужно. Обновитесь через HACS и
> перезапустите Home Assistant.

## 🛠️ Исправлено

- **Восстановлена доставка звонков.** `firebase-messaging` ожидала один параметр `dh` в заголовке `Crypto-Key`, но оператор начал добавлять вторую VAPID-подпись `p256ecdsa`. Интеграция теперь выбирает параметры `dh` и `salt` по имени, нормализует Base64URL и передаёт библиотеке совместимый формат.
- **Исправление изолировано внутри интеграции.** Нормализация применяется только к FCM-клиенту конкретной config entry и не меняет библиотеку глобально — это важно, если в том же Home Assistant установлены другие интеграции с `firebase-messaging`.
- **Home Assistant больше не попадает в горячий цикл ошибок.** Возвращён конечный предохранитель библиотеки: повреждённое соединение штатно останавливается, после чего watchdog может увидеть сбой и начать контролируемое восстановление.
- **Журнал больше не разрастается бесконечно.** После одной контрольной попытки circuit breaker приостанавливает частые переподключения и пробует снова через
  15 минут, 1 час, 6 часов и затем раз в 24 часа.
- **Сбой одного аккаунта не останавливает остальные возможности.** Камеры, замки, баланс, история и другие config entries продолжают работать. Для затронутого аккаунта Home Assistant показывает понятное сообщение в Repairs и автоматически убирает его после подтверждённого восстановления.

## 🔎 Что было причиной

Это не ошибка настроек аккаунта и не проблема пароля. После перехода оператора на VAPID заголовок стал списком параметров вида `dh=<ключ>; p256ecdsa=<подпись>`. Зависимость срезала только первые символы `dh=`, пыталась декодировать весь остаток как один ключ и завершала FCM-клиент до отправки подтверждения. Google повторно доставлял то же сообщение после каждого подключения, поэтому ошибка возвращалась снова.

Отдельный сценарий возникал при разрыве FCM-соединения: отключённый ранее предохранитель позволял клиенту бесконечно перечитывать один и тот же сломанный socket в общем event loop. Traceback рос с каждой итерацией, журнал мог занять гигабайты, а интерфейс Home Assistant — перестать отвечать.

## 🔐 Security

- Утечки токенов, паролей или содержимого push в этой ошибке не обнаружены.
- Перевыпускать access token и повторно авторизовываться после обновления не требуется.
- Диагностика по-прежнему маскирует PII и credentials. Repairs не содержит
  FCM-ключи, токены или push payload, но намеренно показывает локальное имя config entry, чтобы различать аккаунты; это имя может содержать имя жильца и идентификатор аккаунта и доступно только авторизованным пользователям Home
  Assistant.

## ✅ Breaking changes

Нет. `ConfigFlow.VERSION` остаётся `3`; миграция config entry, изменение `entity_id` или `unique_id` не требуются.

## ⬆️ Как обновиться

1. Откройте **HACS → Интеграции → Электронный город** и установите `4.0.1`.
2. Перезапустите Home Assistant.
3. Повторно добавлять аккаунт или удалять существующую config entry не нужно.
4. Если используете события звонка, сделайте один тестовый вызов: event entity, автоматизация или экран вызова должны сработать, а повторяющаяся FCM-ошибка не должна возвращаться.

Если Home Assistant уже завис в цикле FCM-ошибок, сначала установите обновление, а затем выполните полный перезапуск. Откат на `4.0.0` не рекомендуется: именно эта версия содержит исправляемый дефект.

## 🧪 Проверено

- Регрессионный тест воспроизводит реальный production-формат заголовка и проверяет обе исторические ошибки до применения исправления.
- Покрыты разные позиции параметров, восстановление пропущенной метки, работа с protobuf `app_data` и изоляция соседнего FCM-клиента.
- Полный backend suite: **686 tests**.
- На production 13 августа 2026 года listener остался стабильным, а реальный звонок в домофон дошёл до Home Assistant.
