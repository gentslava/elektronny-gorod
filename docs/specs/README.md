# Technical specs

This directory contains agreed technical and product designs that define what the project intends to build and why.

- Use `YYYY-MM-DD-<topic>-design.md` for standalone specs.
- Keep alternatives, constraints, acceptance criteria, and non-goals in the spec.
- Review and approve the spec before creating an implementation plan.
- Keep accepted specs as architectural history after implementation.

Specs are tool-independent and may be used by any human or agent workflow.
